# 接口工具（interface-go）

一个**单文件、零依赖、可离线搬运**的本地 HTTP 接口管理与测试工具。

界面在浏览器内核里运行（Edge/Chrome 的 App 模式独立窗口），数据保存在 exe 同级的
`data` 目录。适合在**网络隔离**的环境里登记外部接口、发请求验证、留存出参快照，
再整体拷到另一台机器上继续使用。

---

## 一、快速开始

```
双击 接口工具.exe
```

首次启动会自动：

1. 在 `127.0.0.1` 上选一个空闲端口启动本地服务（不对外监听，不占固定端口）
2. 用系统自带的 Edge / Chrome 以 **App 模式**打开一个无地址栏的独立窗口
3. 在 exe 同级创建 `data` 目录

> 找不到 Edge/Chrome 时会退化为默认浏览器打开，功能完全一致。

### 命令行参数

| 参数 | 说明 |
| --- | --- |
| `-port 9527` | 指定端口（默认随机；被占用时自动换随机端口） |
| `-no-browser` | 只启动服务，不自动开窗口（配合浏览器手动访问） |
| `-data D:\xx\data` | 指定数据目录（默认 exe 同级 `data`） |
| `-version` | 打印版本号 |

## 二、数据存放与跨环境搬运

```
接口工具.exe
data/
├─ workspace.json      全部接口 + 副本 + Markdown 文档（唯一数据文件）
├─ backup/             每次保存前的自动快照，保留最近 30 份
│   └─ workspace-20261022-153000.000.json
└─ app.log             运行日志
```

**搬运方法：把 `接口工具.exe` 和 `data` 目录一起拷到目标机器，双击即用，数据随行。**

- 若 exe 放在不可写目录（如 `C:\Program Files`），数据会自动改存到
  `%LOCALAPPDATA%\InterfaceGo\data`，界面顶栏会显示实际路径。
- `workspace.json` 是标准 JSON，可直接用文本编辑器查看，也可纳入 Git 管理。
- 额外提供了「导出备份 / 导入备份」按钮，用于在两台机器之间传递数据。

## 三、功能说明

### 1. 支持 HTTP 全部请求方法
`GET / POST / PUT / DELETE / PATCH / HEAD / OPTIONS / TRACE`

请求由 Go 后端真实发出，不受浏览器跨域（CORS）、受限请求头、预检限制，
能拿到完整的状态码、响应头、Cookie 与耗时。

### 2. 接口测试
点「发送」后展示：

- 状态码 + 原因短语（2xx/3xx 绿色，4xx/5xx 红色）
- 耗时（ms）、响应体大小
- Content-Type、响应字符集
- 响应体（JSON 自动格式化，可点「格式化」切换原始/美化）
- 响应头（可切换标签页查看，一键复制）

**出参会随保存一起落库**：点「保存」时，最近一次的响应（状态码/响应头/响应体/耗时）
会与接口配置一起写入 `workspace.json`，重启后打开接口仍能看到上次的出参。

**中文编码**：自动识别 `GBK / GB2312 / GB18030`，老系统返回的中文不再乱码。
**大响应**：超过 5MB 自动截断并标注，避免占用过多内存。

### 3. 三类参数配置

| 参数区 | 说明 |
| --- | --- |
| **路径参数** | 地址里写 `/user/{id}`，工具自动识别 `{id}` 并生成填值行 |
| **URL 参数(Query)** | 参数名 / 值 / 说明 / 启用开关，发送时自动拼接到 URL |
| **请求头(Header)** | 同上，并内置 Content-Type、Authorization、Cookie 快捷插入 |
| **请求体(Body)** | `无` / `JSON` / `原始文本` / `x-www-form-urlencoded` / `form-data` |

每一行都有**启用开关**，关掉的行不会发送（方便在调试时临时屏蔽某个参数）。
表格末行输入内容后会自动追加一行空行，录入多条参数无需反复点「添加」。

### 4. 保存与复制
- **保存**（或 `Ctrl+S`）：把当前配置写入 `data/workspace.json`
- **复制接口**：克隆为一个新接口（名称加 `_副本`，配置全带走，不含原接口的副本列表）

### 5. 接口副本（含出参）
这是本工具的核心能力：**把"接口配置 + 这一次的真实出参"整体冻存下来**。

操作：先「发送」拿到响应 → 点「保存副本」→ 填名称与备注 → 确定。

结果：副本会作为子节点挂在**该接口的下级**，例如

```
▼ 界面测试组
   GET  界面测试-查询用户         1 副本
       ● UI副本-A                200
   GET  界面测试-查询用户_副本
```

**副本与普通接口共用同一编辑器页面**，功能完全一致：

- 顶部有黄色横幅标明当前处于副本，含保存时间与「返回接口」按钮
- 可以修改请求方法、地址、参数、请求体、文档，然后**保存**（写回副本）
- 可以继续**发送**请求，新出参会随保存更新到副本里
- 备注可直接在编辑器里修改；分组跟随所属接口，不可单独修改
- 唯一区别：副本模式下**没有「保存副本」按钮**（副本下不再挂副本）
- 「复制接口」在副本模式下 = 以副本配置新建一个普通接口（相当于把快照变回可编辑接口）
- 「删除」在副本模式下 = 删除副本本身

### 6. 接口文档（Markdown）
「文档」标签页为左编辑右预览的双栏布局，支持：

标题、粗体/斜体/删除线、行内代码、代码块、有序/无序列表、引用、表格、分割线、链接、图片。

文档随接口一起保存在 `workspace.json`，随 exe 一起搬走。
（预览渲染器为内置自研实现，**不依赖任何 CDN**，隔离网内可正常显示。）

### 其他

- 左侧按「分组」组织接口，可折叠；顶部搜索框可按名称/地址/分组过滤
- 顶栏显示当前数据目录实际路径（鼠标悬停可看完整文件路径）
- 删除接口会二次确认；所有保存前都会自动写入 `data/backup`

## 四、从源码构建

```bash
# 需要 Go 1.25+，无需 Node / Rust / 任何前端工具链
go build -o 接口工具.exe .
```

无控制台窗口（更像个桌面应用）的版本：

```bash
go build -ldflags "-H=windowsgui -s -w" -o 接口工具.exe .
```

产物约 10 MB，前端资源已通过 `//go:embed` 打入二进制，**拷走一个 exe 即可运行**。

### 项目结构

```
main.go                    启动本地服务、选端口、拉起窗口、日志与错误弹窗
embed.go                   内嵌 web 目录
internal/model/model.go    数据结构（接口 / 请求 / 响应 / 副本）
internal/store/store.go    workspace.json 原子写入 + backup 轮转 + CRUD
internal/executor/executor.go  真实发送 HTTP 请求、编码识别、响应截断
internal/api/api.go        本地 REST 路由
web/                       原生 HTML + CSS + JS（无框架、无构建链）
  index.html  app.js  style.css  md.js
```

## 五、常见问题

**双击没反应？**
查看 `data/app.log`。若目录不可写，程序会弹窗提示并把数据改存到 `%LOCALAPPDATA%\InterfaceGo`。

**端口被占用？**
默认就用随机空闲端口，一般不会冲突。如需固定端口用 `-port xxxx`，冲突时会自动改随机。

**想恢复误删的接口？**
打开 `data/backup/`，找到删除时间之前的 `workspace-*.json`，复制内容到
`workspace.json`（先关掉程序），或用界面上的「导入备份」。

**接口数据损坏了？**
程序会拒绝覆盖，并把损坏文件重命名为 `workspace.json.broken-<时间>`，同时以空库启动。

**为什么不用 Postman / Apifox？**
它们要么需要联外网、要么体积巨大、要么强制安装运行时。本工具只有一个 exe，
不需要任何额外环境，适合在隔离网、内网服务器、客户现场等场景里随 U 盘使用。

## 六、已知边界

- 不做 Mock / 录制回放，不发任何后台请求（除用户主动点「发送」）
- 不支持文件上传（form-data 仅文本字段）
- 不做环境变量替换（不同环境的地址请直接改 URL，或用「复制接口」区分）
- 响应体 > 5MB 会截断保存
